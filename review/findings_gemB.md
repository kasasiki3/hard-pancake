## 指摘事項（重大度順）

### 1. 【致命（該当時は通信不能・短絡）／確認要】RJ45コネクタ（`J8`・`J9`）の自作フットプリントが「Tab-Up（上扣）」専用のピン順になっており、Tab-Down品では1〜8番ピンが完全逆転する

- **重大度**: 致命（実物がTab-Down品だった場合、作るとCAN1H/LがGND_ISOに短絡し通信不能）／確認要（LCSC図面の実物向き未照合）
- **場所**:
  - `J8`（ピン1〜8、中心 `(7.74, 16.2)`、回転 `-90°`）、`J9`（ピン1〜8、中心 `(7.74, 32.7)`、回転 `-90°`）
  - ネット: `Net-(JP3-A)`, `Net-(JP4-A)`, `Net-(JP3-B)`, `Net-(JP4-B)`, `Net-(J8-Pad4)`, `GND_ISO`
  - ファイル: `tools/gen_fp.py` L15–34、`kicad/pancake.pretty/RJ45_R-RJ45R08P-A004.kicad_mod`、`review/placement.txt` L69–70
- **根拠**:
  - `gen_fp.py` L28–32 では、差込口を `+Y`（KiCad座標系では**画面下向き**）、位置決めボス穴を `(±6.35, +2.54)` に置いた状態で、`Pad 1` を `(+3.57, 0)`（**右端**・ボスに近い列）、`Pad 8` を `(-3.57, -1.78)`（**左端**・ボスから遠い列）に生成している。基板上（`J8`）では左辺（`-X` 側）が差込口となり、部品面（F.Cu）から見て下側 `(7.74, 19.77)` が1番、上側 `(9.52, 12.63)` が8番になっている。
  - ISO/IEC 8877（8P8C）規格および KiCad 10 標準フットプリントとの幾何照合の結果、差込口を `+Y`（下）に向けた Top View では、**Tab-Down（下扣：ラッチ爪が基板側）** のコネクタ（例: `RJ45_Amphenol_54602-x08_Horizontal`、`RJ45_Ninigi_GE`）は必ず **左端が Pad 1、右端が Pad 8** となる。一方、**Tab-Up（上扣：ラッチ爪が反基板側）** のコネクタ（例: `RJ45_Connfly_DS1128-09-S8xx-S_Horizontal`）のみ右端が Pad 1 となる。
  - 採用部品 `R-RJ45R08P-A004`（Ckmtw製、図面型番 `ZP5JA88-1`、LCSC `C385834`、全塑无筋无灯弯插）が標準的な Tab-Down（下扣）であり、かつメーカー図面の推奨ランドパターンが **Bottom View（はんだ面視）** で描かれていたものを Top View として座標化した可能性がある（推測：`datasheet/` に当該PDFが無く実物・原本図面の視点は未確認）。もし実物が Tab-Down であれば、**ピン番号が 1↔8, 2↔7, 3↔6, 4↔5 と完全逆転** し、桔梗の雛形に対して 1-2番（CAN1 H/L）が `GND_ISO`（7-8番）に落ち、3-6番（CAN2）と 4-5番（12V）も入れ替わる。
  - あわせて、`J8`/`J9` のボス穴中心は `x = 5.20mm` だが、一般的な同型ライトアングルRJ45はボス中心〜前面が `7.6〜8.1mm` あるため、基板左端（`x = 0`）からコネクタ前面が約 `2.4〜2.9mm` 突出する（`readme.md` L88 でも前面距離は未確認）。
- **直し方**:
  - EasyEDA / JLCPCB 部品ライブラリで `C385834` の公式フットプリント（Top View での Pad 1 座標・奇偶列の前後関係・前端外形線）を必ず開いて照合する。
  - 実物が Tab-Down（下扣）である場合は、`gen_fp.py` L30 の X座標を `-3.57 + 1.02 * (n - 1)` に反転させ（奇偶列の `y = 0` / `-1.78` も実物のピン列と一致しているか確認）、`J8`・`J9` 周辺を再配線する。

### 2. 【致命（IDRIVE=75kΩ変更時）／重大（現行C45〜C47未実装時）】ローサイドソース `SPx` の負サージが公称条件でも絶対最大定格（`-3V`）を超過しており、`IDRIVE=75kΩ` 変更候補では `SHx`/`SPx` が破壊領域に入る

- **重大度**: 致命（`readme.md` L42 の `IDRIVE=75kΩ` 変更時は `-11.7V` / `-10.3V` でIC破壊）／重大（現行の `C45〜C47` 未実装でも負側が `-3.37V`〜`-6.37V` に達し定格超過）
- **場所**:
  - `U2.11 (SPA)`, `U2.14 (SPB)`, `U2.21 (SPC)`、`U2.9 (SHA)`, `U2.16 (SHB)`, `U2.19 (SHC)`
  - `C45` `(21.6, 50.1, B面 DNP)`, `C46` `(39.0, 50.1, B面 DNP)`, `C47` `(56.4, 50.1, B面 DNP)`、`R7` `(50.8, 24.2)`
  - ファイル: `sim/bridge_sim.py` L64、`sim/run/*.raw`、`readme.md` L42, L56
- **根拠**:
  - `datasheet/drv8323r.pdf` p.12（7.1 Absolute Maximum Ratings）より、`SPx, SNx` ピン電圧の絶対最大定格は **連続 `-1V`〜`+1V`、過渡（200ns）`-3V`〜`+3V`**、`SHx` ピンは **過渡（200ns）`-7V`〜`VVM+7V`**。
  - `sim/bridge_sim.py` L64 は `.meas TRAN sh_pk MAX V(sp)` のみで **正側ピークしか測定しておらず、負側ピーク `MIN V(sp)` がログに出力されていなかった**。
  - `sim/run/*.raw` の波形バイナリを直接読み出して `V(sp)` の最小値・継続時間を計測した結果は以下の通り:
    - **現行構成（`C45〜C47` 未実装、30A、25.2V、IDRIVE=30/60mA）**:
      - 公称寄生 x1.0（`A_30A_in.raw`, `B_30A_in.raw`, `C_30A_in.raw`）: 正側は `+1.73V` だが、**負側は `sp_min = -3.36V`〜`-3.37V`**（`-3V` 超過 3ns、`-1V` 未満 30〜33ns）。
      - 寄生 x1.3（`loop x1.3 30A.raw`）: ログ上の正側は `+2.35V` だが、**負側は `sp_min = -4.30V`**。
      - 寄生 x2.0（`loop x2.0 30A.raw`）: `readme.md` L56 で「未実装だと2倍で3.8V」と記載されているのは正側 `+3.75V` であり、**負側は `sp_min = -6.37V`**（`-3V` 未満が 28ns、`-1V` 未満が **202.7ns** 続き連続定格も超過）。
    - **`readme.md` L42 の変更候補 `IDRIVE = 75kΩ（60/120mA）`（`idrv60_120_in.raw` / `out.raw`）**:
      - `NTMFS5C628NL` の `QGD = 4.5nC`（`datasheet/C145537(MOSFET).pdf` p.2）は `VDS = 48V` 条件の値であり、`VBUS = 25.2V` では実効ミラー電荷が約半分（約 `2.2nC`）しかない。このため 60/120mA 駆動では 10–90% 遷移時間が `23.5ns` まで急峻化し、**`sw_min = -11.70V`（`SHx` 定格 `-7V` 超過）、`sp_min = -10.30V`、`sp_max = +6.29V`（`SPx` 定格 `±3V` を大幅超過、`-3V` 未満が 94.4ns、`-1V` 未満が 372.1ns）** となり DRV8323RH が破損する。
    - **`C45〜C47`（1µF 100V 1206）実装時**:
      - 公称 x1.0（`loop x1.0 30A C45.raw`）: **`sp_min = -1.63V` / `sp_max = +0.91V`**。
      - 寄生 x2.0（`loop x2.0 30A C45.raw`）: **`sp_min = -2.01V` / `sp_max = +1.53V`**（`-3V` 超過 0ns、`-1V` 未満 17.3ns）に劇的に改善する。
- **直し方**:
  1. `C45`・`C46`・`C47`（1µF 100V X7R 1206）を「実装するか未決（DNP）」ではなく **必須実装** とする（裏面手付けでもよいが、可能なら表面の `Q1/Q3/Q5`〜`Q2/Q4/Q6` 横に配置すると片面PCBAで一括実装できる）。
  2. `readme.md` L42 から `IDRIVE = 75kΩ（60/120mA）` への引き上げ候補を削除する（現行 18kΩ = 30/60mA で 10–90% 立ち上がり `44.8ns` と SLVAF66 目安の 100〜300ns より既に速いため、試作でリンギングが大きい場合の変更先は `0Ω（AGND直結、10/20mA）` 側とする）。

### 3. 【重大】絶縁CANトランシーバ `CA-IS2062A`（`U6`）のデカップリングコンデンサが同一層で直結されず、全て幅 0.2mm 線＋個別ビア経由になっておりデータシート禁止事項に違反

- **重大度**: 重大（内蔵絶縁DC-DCの動作不安定・放射ノイズ増大・通信エラーの恐れ）
- **場所**:
  - `U6` `(31.4, 14.0, rot=180°)` の Pin 5 `GNDP1` `(33.83, 13.68)`、Pin 6 `VDDP` `(33.83, 13.03)`、Pin 7 `VDDL` `(33.83, 12.38)`、Pin 8 `GND1` `(33.83, 11.72)`、Pin 9 `GND2` `(28.98, 11.72)`、Pin 10 `VISOIN` `(28.98, 12.38)`、Pin 11 `VISOOUT` `(28.98, 13.03)`、Pin 12 `GNDP2` `(28.98, 13.68)`
  - `C38` `(37.4, 13.25)`, `C39` `(35.6, 13.4)`, `C40` `(35.6, 10.4)`, `C41` `(25.0, 13.4)`, `C42` `(26.8, 13.6)`, `C43` `(26.2, 10.6)`
  - ファイル: `tools/gen_pcb.py` L142–148、`tools/route_pcb.py` L244–258、`review/img/F.Cu.png`
- **根拠**:
  - `datasheet/CA-IS2062A(絶縁CANトランシーバ).pdf` p.4 表6-1: `GNDP1` と `GND1`、`GND2` と `GNDP2` は「PCB上で直接短接すること」。
  - 同 p.19 図10-3 および p.20（10.3 PCB布线指导）: 各デカップリングコンデンサは対応する電源ピンから **2mm以内** に配置し、**「上述去耦电容和器件必须放在同一层 PCB，禁止将电容和器件放在不同层然后通过过孔相连」**（ビアを介して別層経由で接続することを明確に禁止）。内蔵DC-DC（显性時最大 `IVDDP = 150mA`、p.8）はオンチップマイクロトランスを高周波駆動するため、ビアのインダクタンスがスイッチングノイズを直撃する。
  - 実基板を解析した結果、`route_pcb.py` が `GND` / `GND_ISO` / `+3V3` を内層プレーン落しとして処理したため、F.Cu の銅箔が他配線のクリアランスで分断されており、以下のように **すべて幅 0.2mm トレース＋個別ビアで内層経由接続** になっている:
    - `U6.5 (GNDP1)` → 幅0.2mm → ビア `(34.8, 13.8)`、`U6.8 (GND1)` → 幅0.2mm → ビア `(34.3, 11.1)`、`C39.2 (GND)` → 幅0.2mm → ビア `(35.6, 14.7)`（F.Cu上で直結なし）。
    - `U6.7 (VDDL, +3V3)` → 幅0.2mm → ビア `(34.8, 12.3)`、`C40.1 (+3V3)` → 幅0.2mm → ビア `(36.5, 11.5)`（`In2.Cu` 経由）。
    - 絶縁側も `VISOIN` トレースが間を抜けるため、`U6.12 (GNDP2)` → 幅0.2mm → ビア `(28.0, 13.8)`、`U6.9 (GND2)` → 幅0.2mm → ビア `(28.0, 11.8)`、`C42.2` → ビア `(27.0, 14.8)` と分断されている。
  - さらにピン〜パッド中心距離も `U6.6`–`C38.1 (10µF)` が **3.64mm**、`U6.11`–`C41.1 (10µF)` が **4.02mm**、`U6.10`–`C43.1 (1µF)` が **2.68mm** と 2mm 規定を超えている。
- **直し方**:
  - `CA-IS2062A.pdf` p.19 図10-3 の推奨パターンどおり、`C39 (0.1µF)`・`C38 (10µF)` を Pin 5–6 横 2mm 以内、`C40 (1µF)` を Pin 7–8 横 2mm 以内、`C42 (0.1µF)`・`C41 (10µF)` を Pin 11–12 横 2mm 以内、`C43 (1µF)` を Pin 9–10 横 2mm 以内に並べる。
  - `gen_pcb.py` で F.Cu 上の太い固定配線または小ゾーン（幅 0.5mm 以上）を設け、**ICの電源・GNDピンが必ずコンデンサのパッドを F.Cu 上で直接通過してからビアで内層プレーンへ落ちる** ように修正する。

### 4. 【重大】自動配線（`route_pcb.py`）のプレーン落し仕様により、`DRV8323 VREF`（`C11`）・`3.3V LDO`（`U1`–`C5`）・`MCU VDDA/VREF+`（`U3`–`C31..C34`）がパスコンを通らず幅 0.2mm 線＋個別ビアで内層へ落ちている

- **重大度**: 重大（電流センス基準 `VREF/2`・ADC/COMP基準へのデジタルノイズ混入、LDO出力インピーダンス悪化）
- **場所**:
  - `U2.26 (VREF, +3V3)` `(47.49, 26.3)` と `C11` `(50.8, 27.3)`
  - `U1.5 (VOUT, +3V3)` `(56.94, 2.85)` と `C5` `(59.1, 3.8)`
  - `U3.20 (VREF+)` `(60.3, 14.89)` / `U3.21 (VDDA)` `(59.8, 14.89)` と `C31`〜`C34` `(58.0〜60.5, 9.0〜13.0)`
  - ファイル: `tools/route_pcb.py` L200–207, L244–258、`review/img/F.Cu.png`
- **根拠**:
  - `route_pcb.py` は `+3V3`・`GND` をプレーンネット（`wclass = 0` すなわち **線幅 0.2mm**）として各パッドから独立に最寄りのビアへ落としているため、ICピンとデカップリングコンデンサが F.Cu 上で直結されていない。
  - `U2.26 (VREF)` は 40倍電流センスアンプ3chの基準電源（`VREF/2 = 1.65V` オフセット生成元、`drv8323r.pdf` p.31 表8-1 で VREF–AGND 間 0.1µF 指定）であるが、`U2.26` はビア `(48.4, 26.2)` で `In2.Cu (+3V3)` プレーンに落ち、`C11.1` は約 3mm 離れた別ビア `(50.6, 26.6)` で同じデジタル `+3V3` プレーンに落ちている（`AGND` Pin 35 とも別ビア）。
  - `U1 (RT9013-33GB)` も基板全体の `+3V3`（約 60〜100mA）を供給する LDO 出力ピン `U1.5` が **幅 0.2mm の細い線1本** でビア `(57.4, 3.6)` に落ち、位相補償・出力コンデンサ `C5 (1µF)` は別ビア `(60.0, 3.3)` に落ちている。
  - `U3 (STM32G431)` の `VREF+ (Pin 20)`・`VDDA (Pin 21)` もフィルタ無しで個別ビアから `In2.Cu (+3V3)` デジタル電源面に直結しており、MCU自身のスイッチング電流による `+3V3` リップルが ADC・内蔵DAC・COMP しきい値に直接重畳する。
- **直し方**:
  - `U2.26 (VREF)` のすぐ横（1.5mm以内）に `C11` を移動し、F.Cu トレースで `U2.26 → C11.1 → ビア` の順に直列通過させる。
  - `U1.5 (+3V3)` から `C5.1` へ幅 `0.5〜0.8mm` の F.Cu 固定トラックを引き、`C5.1` パッドからビア2本以上で `In2.Cu` に落とす（`U1.2`・`C4.2`・`C5.2` の GND も F.Cu で直結する）。
  - `U3.20 (VREF+)`・`U3.21 (VDDA)` は F.Cu トレースで `C34 (100nF)`・`C33 (1µF)` のパッドを通過させてからビアへ落とす（余地があれば `+3V3` との間に 10Ω 抵抗またはフェライトビーズを挿入する）。

### 5. 【重大】パワーMOSFET `Q1`〜`Q6` のドレイン露出パッド内にサーマルビアが 0本（SLVA959 / SLVAF66 定石違反）

- **重大度**: 重大（30A駆動・連続負荷時のMOSFET放熱悪化）
- **場所**:
  - `Q1, Q3, Q5` `(22.8 / 40.2 / 57.6, 46.9)`、`Q2, Q4, Q6` `(22.8 / 40.2 / 57.6, 54.3)` の各 Pad 5（Drain Exposed Pad）
  - ファイル: `tools/gen_pcb.py` L384–394、`review/img/F.Cu.png`、`review/img/In1.Cu.png`
- **根拠**:
  - パッドポリゴンと全ビア座標の包含判定により、`Q1`〜`Q6` のドレインパッド（約 `4.06×4.56mm`）内部にあるサーマルビアは **すべて 0本** であることを確認した（ローサイドの相帯ビア群はパッケージ左外の `x = c-10.1 .. c-4.8` にあり、ハイサイドの VBUS ビアもパッド外周から離れた位置にある）。
  - TI SLVA959（Section 2.1 Thermal Vias）および SLVAF66 が示す通り、SO-8FL パッケージの熱の大半はドレインパッド直下から内層・裏面へ逃げる。`datasheet/C145537(MOSFET).pdf` p.1 Note 2 の $R_{\theta JA} = 40^\circ\text{C/W}$ は 2oz 銅箔 $650\text{mm}^2$ 条件であり、1oz（35µm厚）で直下ビアが 0本だと F.Cu の面内熱抵抗がボトルネックとなって実効熱抵抗が上昇する（`設計チェック.md` L48 で 30A 時 1個あたり 7.6W 発熱）。
- **直し方**:
  - 各 MOSFET のドレインパッド直下にサーマルビア（各6〜9本、穴径 φ0.2〜0.3mm）を追加する（JLCPCB標準工程ではんだ吸い上がりを防ぐため、裏面ソルダマスクをテンティングにし、F.Paste を4分割してビア直上のペースト開口を避けるか、パッド境界から 0.25mm 外側の全周に φ0.3mm ビアを密接配置する）。

### 6. 【重大】3相過電流保護の `COMP1/2/4` が片極性のみのため、FOCの特定電気角位相で最大約2倍（60〜70A）までCOMPが遮断しない死角がある

- **重大度**: 重大（過電流保護の位相依存抜け）
- **場所**:
  - `U3.9 (PA1 / COMP1_INP)`, `U3.15 (PA7 / COMP2_INP)`, `U3.16 (PB0 / COMP4_INP)`
  - ファイル: `readme.md` L18, L45、`設計チェック.md` L71
- **根拠**:
  - DRV8323RH の電流センス出力は $V_{\text{SOx}} = 1.65\text{V} - 0.02\text{V/A} \times I_x$（`drv8323r.pdf` p.42 式3、モーターからローサイドシャントへ吸い込む方向が $I_x > 0$）。
  - `COMP1/2/4` は `DAC3` しきい値（例: $+35\text{A} \Rightarrow 0.95\text{V}$）を下回る片方向（吸い込み正電流）しか検出できない。
  - 3相モーターでは $I_A + I_B + I_C = 0$ のため、**1相からモーターへ大電流を吐き出し（例: $I_A = -68\text{A} \Rightarrow V_{\text{SOA}} = 3.01\text{V}$）、残り2相で半分ずつ吸い込む（$I_B = I_C = +34\text{A} \Rightarrow V_{\text{SOB}} = V_{\text{SOC}} = 0.97\text{V} > 0.95\text{V}$）電気角位相（60°周期で発生）では、3相とも `0.95V` を下回らず、相電流が約 68A に達するまで COMP ブレークが作動しない**。
  - 常温（$R_{\text{DS(on)}} \approx 2.0\text{m}\Omega$）では DRV8323 の VDS 監視（0.13V ≒ 65A、4µs デグリッチ）も約 65A まで動作しないため、30〜35A 制限の意図に対して最大約2倍の電流が流れうる（ブラシ付きDCのHブリッジ駆動でも電流方向・還流モードによって片側しか正電流にならない場合がある）。
- **直し方**:
  - 回路変更なしで対策可能: STM32G431 の **ADC アナログウォッチドッグ（`AWD1`/`AWD2`/`AWD3`）** は上下限ウィンドウ監視が可能なため、PWM周期ごとの電流AD変換に対して正負両極性しきい値（例: $\pm 32\text{A} \Leftrightarrow 1.01\text{V}\sim 2.29\text{V}$ 範囲外）を設定し、`TIM1_AF1` レジスタの `AWDF1BK0E` 等を有効にして CPU 割り込みを介さず直接 `TIM1` ハードウェアブレークをかける構成を `readme.md` の保護仕様に追加する。
  - または `COMP1/2/4` のしきい値をピーク30A仕様に対してやや低めにする場合でも、上記位相では他2相が $I_{\text{peak}}/2$（30A時に +15A）にしかならないため、やはり両極性の ADC AWD ハードブレーク併用が有効である。

### 14. 【確認要】STM32G431 の `DAC1_CH1` 内部接続と `PA4`（エンコーダ2 `TIM3_CH2`）の共用、および原本未入手データシート・未確認事項

- **重大度**: 確認要
- **場所**: `U3.12 (PA4)`, `U3.8 (PA0 / VBUS_SENSE)`、`Y1` `(68.7, 19.5)`、`readme.md` L47, L85–98
- **根拠**:
  - **`PA4` と `DAC1_CH1` 内部接続（`readme.md` L47）**: RM0440 仕様上、`DAC_MCR` レジスタで `MODE1[2:0] = 011b`（出力バッファ無効・オンチップペリフェラルのみ接続）を **`DAC_CR.EN1 = 1` にする前に設定** すれば、`PA4` 外部ピンへのアナログスイッチは切り離され、`PA4` を `TIM3_CH2 (AF2)` として併用しつつ `COMP3_INM` へ `DAC1_CH1` を供給できる。ただし順序を誤って `MODE1 = 000b` のまま `EN1 = 1` にすると、プッシュプル出力の MT6701（`R24 = 100Ω` 経由）と DAC バッファが衝突する。
    - *より確実な代替案*: `COMP3_INM` の基準には `DAC1` を使わず STM32 内蔵基準電圧 **`VREFINT`（約 `1.212V`）** を直接選択し、VBUS 分圧抵抗 `R1/R2` を `100kΩ / 4.22kΩ`（または `120kΩ / 5.1kΩ`、約 30V で 1.21V 到達）に変更すれば、`DAC1` と `PA4` の競合懸念をハードウェア的に完全解消できる（または `ADC1` のアナログウォッチドッグ `AWD` → `TIM1` ハードウェアブレークを使用する）。
