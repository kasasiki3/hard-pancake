# 固いパンケーキモータードライバ

5010クラスのBLDCをFOCで駆動し、ついでにRZ-735等のブラシ付きDCモーターも駆動する、CAN-FD接続の1ch 3相モータードライバ。
当面はブラシ付き（735）で使い、将来BLDC（5010）へ流用する。基板は同一、ファームの切り替えで対応する。

決定済みの部品は [BOM.md](BOM.md)。

## エンコーダ端子の信号

- 両ポートとも JST XA 6ピン（縦置き）：1: VCC、2: GND、3: GND、4: A、5: B、6: Z
- 電源はポートごとに3ピンはんだジャンパで切替（JP5: ポート1 既定3.3V/5V、JP6: ポート2 既定5V/3.3V）。
- MT6701はABZとSSIが同じピンを共用する（A=DO、B=CLK、Z=CSN）。どちらを出すかはセンサ側のMODEピンで選ぶので、同時には使えない。
- ABZはタイマのエンコーダモードに入れる（ポート1: TIM4 PB6/PB7＋Z PB5、ポート2: TIM3 PA6/PA4＋Z PA5）。
- ポート1のA/BはSPI3（PB4 MISO、PB3 SCK）にも配線してあり、SSIのときはSPIを受信専用で使う。CSNはPB5をGPIO出力にして駆動する。

## 設計方針

- 3相ハーフブリッジ×3を常に実装し、ブラシ付きDCは2相（例: U-V）でHブリッジ駆動する。残り1相は未使用。
- プログラムを間違えても壊れないことを優先する。貫通・短絡・ロックの保護はDRV8323RHの抵抗設定で行い、マイコンに頼らない。
- 電流検出はDRV8323RH内蔵アンプを使う。
- 部品はJLCの在庫が多く単価の安いものを選ぶ。

## ファームの前提

- 駆動電流はIDRIVE 18kΩで30/60mA、VDS監視は18kΩで0.13V、ゲインはDVDD直結で40倍、PWMは6x。試作で波形を測り、IDRIVEを75kΩ（60/120mA）やVDSを75kΩ（0.26V）へ変更できる。ただしIDRIVEを上げるのは試作でSPxの負側を測ってから（C45〜C47が無いと−8.6Vになる計算）。スナバのパッドは削除した（2026-11-26）。
- デッドタイムはDRV8323RHがゲート電圧を見て自動で入れる（＋100ns）。ファームでもTIM1に500ns（DTG=85）を入れる。
- ENABLEはPB2（リセット中は内部プルダウンで停止）、CALはPB1、nFAULTはPB12。
- 電流はPA1（COMP1）、PA7（COMP2）、PB0（COMP4）で3相とも過電流を見る。しきい値はDAC3を使う（DAC1の外部出力はエンコーダ2のPA4/PA5と重なる）。正の電流でアンプ出力は下がる。
- 起動直後にUCPDのデッドバッテリーを無効にする（UCPD1_DBDIS=1）。SWOは使わない（PB3がエンコーダ1のB）。
- VBUSの過電圧はCOMP3（PA0）→TIM1ブレークで止める（しきい値30V目安=1.59V）。基準はDAC1の内部接続を使う想定（PA4をエンコーダ2に使いながらできるかはRM0440で未確認）。できなければADCのアナログウォッチドッグで止める。
- ENABLEを下げる前にINHx/INLxを全てLにする（PWM中に下げるとゲートがHi-Zのまま残る。データシート8.4.1.1）。
- VDS保護は4msごとに再試行し続けるので、nFAULTでTIM1を止めたままにする（AOE=0）。ゲート故障（GDF）の解除はENABLEを8〜40µs下げる。
- CANが途切れたら止める。低電圧（LiPo保護）で止める。電流は連続約6A（入力コンデンサのリップル定格: 1.4A×20kHz帯の係数0.70×3個=2.94Arms、データシートp.8）・ピーク30Aの時間をI²tで制限する。
- 電流のサンプルは低側が3µs以上開くデューティに制限する（40倍の整定が1.2µs）。
- COMPは片側（正の電流）しか見ないので、1相が−2I・2相が+Iの角度では各相のCOMPに半分しか出ない。ADCのアナログウォッチドッグで上下とも見る。
- CSAのオフセットは±4mV（±8A相当）、ドリフトは10µV/℃（20mA/℃）。CAL（PB1）での較正を起動時だけでなく停止中・ゼロベクトル中にもやり直す。
- NTC_SENSE（PB11）にはコンデンサが無く源インピーダンスは5kΩなので、ADCのサンプル時間を長く（92.5サイクル以上）取る。
- 高側ON中の相–GND短絡はシャントを通らず、VDS監視（4µs）だけが守る（LTspiceの近似で176〜685A、`review/findings_opus.md`）。
- ウォッチドッグはオプションバイトでハード起動にし、デバッグ停止中はTIM1の出力を止める。

## 決定の経緯

- マイコンをSTM32G431CBT6からSTM32G474CBT6（C730123）に変更した（2026-11-26）。G431CBT6がJLCで在庫切れのため。同じLQFP-48で全ピン互換（ST公式ピンデータ、`review/まとめ.md`）、Flashは同じ128KB。64KBのG431C8T6は、FOC＋FDCANの参考ファーム（FOC2）をビルドすると-O2で41KB、-O0で65KBになり余裕がないので採らなかった。UFQFPN-48のCBU6はピン番号が25本ずれ、基板の作り直しになるので採らなかった。
- 基板の見直しを4周した（2026-11-26、LTspice `sim/`、Gemini 4 Neonの査読）。81×68mm。直したもの: ゲート線の余分なループ、シャントのSP銅、降圧の入力ループ、TVSの位置、水晶横のVBUS線、ESDの並び、検出線とゲート線の間隔（0.5mm以内の並走は各2mm以下）。LTspiceの近似ではC45〜C47を実装すると、ループの寄生が想定の2倍でもSPxが±3V（200ns）に収まる。縮小案のうち、相の間隔15mm・高さ66mmは、上半分の幅とVBUSの抵抗のため採らない。
- 回路・基板を査読した（2026-11-26、Gemini 4 Carbon High×2・Opus 5.5 max、[review/まとめ.md](review/まとめ.md)）。作ると動かない・壊れる誤りは無し。直したもの: 主要部品のLCSC番号（純正品を指定。互換品(ES)が入らないように）、DRVのサーマルビアの裏面をソルダマスクで塞ぐ、D1を単方向の記号に、モーターパッドをBOMから除外、C12/C13のGNDをベタ接続、シミュの低側ドライバをPGND基準に修正（データシート表6-4）。修正後のシミュ（`sim/run_review.py`）ではC45〜C47が無いとSPxの負側が−3.3V（寄生2倍で−6.3V、絶対最大は200nsで−3V）、付けると−0.6V（−0.9V）。裏面に部品を置かない方針なので、C45〜C47は表面の高側FETの左（VBUSバーの上）へ移し、SPは裏面のSPベタを上へ広げて2本のビアでつないだ（FETの右は裏面がゲート・検出線の束でビアを打てない）。真下より配線の誘導分が増え、シミュ（`sim/run_c45L.py`）では3nHで−1.6V（寄生2倍で−2.0V）、5nHで−2.1V（−2.9V）。部品はJLCの基本部品の1µF 50V X7R 1206（C1848）。容量はほぼ効かず、25V時の実効0.3µFでも−1.3V（`sim/run_c45C.py`）。試作でSPxを測る。スナバ（裏面の未実装パッド）は削除した（シミュでVDSの跳ね31.6V対31.3V）。製造データは `python tools/export_jlc.py` で `kicad/production/` に出す（発注時の注意は `kicad/production/発注メモ.md`）。
- 基板を作った（2026-11-25、`kicad/pancake.kicad_pcb`）。81×68mm（角R4.5）、4層、1oz。部品は全て表面（裏面には部品を置かない）。左辺にRJ45×2とXT60、下辺にモーター出力3つとエンコーダ2つ（右端、右下ねじ穴の奥に縦に並べる）。XT60の＋がそのままVBUSバーの端で、電解3個は各相のFETの隣に1個ずつ置く。VBUSバーはL1・L3・L4、L2はGND、相の帯と下端のGND帯は4層。XT60からの往復抵抗の計算値（`tools/check_pcb.py`、1oz）: A 1.2、B 1.9、C 2.5mΩ、電解→FETは0.15〜0.28mΩ。波形は `sim/run_phases.py`（LTspice、近似モデル）。ブラシ付きはB–Cで使う（Bはゲート線が最短、温度センサはCの横）。島との銅箔の間隔は3.2mm以上。作り方は `tools/gen_pcb.py`。仮に決めたもの: エンコーダはJST XH 5ピン（B5B-XH-A、SWDのPHと挿し間違えない）、モーターのパッドと取付穴はmoteus r5（Apache-2.0）の形。パッドは6mm角へ1.47倍（中央2.8mm穴、四隅1.3mm穴、ビア20個）、取付穴はM3（3.2mm穴、5.45mmパッド、ビア8個、どこにもつながない）を角のRと同心で四隅に置く（72×59mm間隔、左上はCANの島の銅を避けてある）。ENC1はABZ/SSI、ENC2はABZで、信号名をシルクに書いた。KiCad標準のXT60は1番が−で回路図と逆なので、番号を入れ替えたフットプリントを使う。
- 設計チェック（2026-11-25、[設計チェック.md](設計チェック.md)）の指摘を反映した。仕様のピークを40Aから30Aにした（VDS監視0.13Vは高温で約35Aで働き、40Aを保証できないため）。シャントの検出線（SPx、SNx）とVDRAINにネットタイ、各相にVBUS〜低側ソースの未実装パッド（1µF 100V 1206）、テストポイント20個を追加。VBUS_SENSEを10nFから1nFにした。FETはonsemi純正を指定する（互換品のNTMFS5C628NLT1G(ES)はゲート電荷102nCでtDRIVE 4µsに余裕がない）。電源の逆接続はXT60の極性で防ぎ、基板に対策は入れない。

- JLCのフィーダ費と在庫のため、受動部品をBasic／Preferredに寄せた（2026-11-25）。1µF・4.7µF・10µF・22µFはX5R（DRV8323RHの指定はX5RかX7R）、チャージポンプの47nFは50V品、100nF 100Vは0805。CAN終端の60.4Ωは120Ω×2並列、5V降圧の分圧は100k/18k（5.02V）。リセットボタンは在庫5個のTL3342からTS-1187A-B-A-Bに変更。相の2.2µF 100VだけはBasicに100V品が無いのでExtendedのまま。
- 減速の回生は電池に戻すのを基本とし、電流を30A程度に制限する（2026-11-25）。短絡ブレーキは使わない。735は約0.115Ωなので、全速で短絡すると約217Aになるため。
- 入力の電解コンデンサを220µF 50V×2からハイブリッドの100µF 63V×3（118EC447、1個1.4A、30mΩ）に変更した（2026-11-25）。前のものはリップルが1個220mAで足りず、50VはTVSのクランプ48.4Vに余裕がないため。
- 電源側に30Aのブレードヒューズを外付けする（2026-11-25）。基板には載せない。役目は配線・電池の焼損とロックしっぱなしを止めること。FETの短絡はVDS監視、通常の電流はCOMPの30〜35A制限（ファーム）で守る。RZ-735VA 9517はメーカー値で停動156A（18V、約0.115Ω）なので、ファームの電流制限は必須。
- ゲートドライバをDRV8300DRGERからDRV8323RHに変更した（2026-11-25）。プログラムを間違えても壊れないように、貫通防止（VGS監視）と短絡・過電流の保護（VDS監視）をマイコンなしで働かせるため。12V電源（TPS7A4101）、5V降圧（LMR51625）、ゲート抵抗、ブートストラップは不要になった。
- CAN1/CAN2の切替をスライドスイッチからはんだジャンパに変更した（2026-11-25）。普段はCAN1だけ使うため。
- 回路レビュー（2026-11-25）を受けて修正した。終端ジャンパをCANH・CANLの両方に入れた。LED2をPC14からPB9へ、エンコーダ1 ZをPC13からPB5へ移した（PC13〜15は出力の制限がある）。
- CANトランシーバを非絶縁のTCAN1044Vから絶縁のCA-IS2062Aに変更した（2026-11-25）。電源のマイナス線だけが外れたとき、モーターの戻り電流がCANケーブルのGNDに流れるのを防ぐため。信号は容量結合（OOK変調）、島側の5Vは内蔵の絶縁DC-DCで作る。VISOOUTとVISOINは直結する（開放禁止）。
- 回路図はシート内を配線でつなぎ、ネットラベルを使わない形に作り直した（2026-11-23）。シートは電源・制御（MCU・CAN・エンコーダ）・パワー段の3枚で、シート間の信号は階層ラベルとルートシートの配線でつなぐ。配線が交差しにくいように、GPIOの割り当てを変更した（エンコーダ2 Z→PA5、LED1→PB10、LED2→PC14）。TCAN1044VのSTBはGNDに固定した（常時ノーマルモード）。
- USB Type-C・CH340C・自動書き込み回路を削除した（2026-11-24）。デバッグはSWDとCANで行い、机でMCUだけ動かすときはST-Link V2互換品の5Vで給電する。純正のST-Link（V2/V3MINIE）は基板へ給電できない（T_VCCは電圧検出の入力）ので、互換品を使う前提。SWDは小さく逆挿しできないJST PHにした（2.54mm 2×5ボックスヘッダは20×9mmで大きすぎる）。
- USB Type-Cを追加した（2026-11-23、翌日削除）。目的はデバッグ・書き込み・給電。MCU内蔵USBはFDCANとピン（PA11/PA12）が重なるため使わず、CH340CでUSART2につなぐ。
- エンコーダのシリアルはSPI（9ピン）をやめ、MT6701のSSIをABZと同じ3本で受ける形にした（2026-11-23）。I2Cはオープンドレインでケーブルのノイズに弱いため使わない。
- MCUはUFQFPN-32（KBU6）から LQFP-48（CBT6）に変更（2026-11-23）。エンコーダ2ポート＋SPIを追加するとPWM・OPAMP・FDCAN・SWDと合わせてGPIOが足りないため。CBT6の方が単価も安く在庫も多い（$3.09／4,672個 vs $7.23／350個）。
- 電源入力はXT60、モーター出力は基板に直接はんだ付けする（2026-11-24）。
- FETは60V品（NTMFS5C628NL、ODrive v3.4 48V版で採用実績）に仮決定（2026-11-22）。
- ゲートドライバはDRV8300DRGER、ゲート駆動電源はTPS7A4101で12V（2026-11-22）。DRV8300のGVDDは最大20Vで6Sを直接入れられないため。
